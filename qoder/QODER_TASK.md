# Qoder 开发任务书：研究续航站

状态：仅需求准备，尚未在 Qoder 开发，不能作为已完成参赛作品。

## 项目目标

为学习和科研用户解决“隔几天回来，忘记上次进展、失败尝试和下一步”的问题。用户保存一次学习/实验记录，下次打开能看到有依据的进度回顾和下一步行动。核心技术采用 PowerContext 持久化上下文。

## 交给 Qoder 的开发指令

请在独立 qoder/ 目录完成项目主要开发，不修改 gaode/、dify/、stepfun/、minimax/，不修改其他题目分支。Git 基线为 oceanbase/powercontext 的 2026-competition-ecosystem，创建全新分支 2026-competition-ecosystem-qoder。先核对该分支是否存在，存在则检查内容，不能覆盖。

请先形成实现计划，再完成源码、测试和运行说明，并保留真实对话记录。

做一个“研究续航站”Web 应用：
1. 创建研究项目，录入目标。
2. 保存本次进展、已尝试方法、遇到的问题和下一步。
3. 通过 PowerContext HTTP API 写入真实记忆，保存成功后才显示成功。
4. 重新打开应用后，根据项目范围召回历史，展示可追溯的原始记录与续做清单。不要使用进程内数组或浏览器 localStorage 替代 PowerContext。
5. 支持项目切换，项目 A 的记录不得出现在项目 B。
6. PowerContext 不可用时如实报错，不伪造历史或生成成功提示。
7. 首版可以用结构化输入与模板生成续做清单，无需模型密钥；如果使用模型，必须说明供应商、版本和配置，模型不得编造未发生的进展。
8. 采用轻量 Web UI + 服务端代理，服务端保存 PowerContext 凭据，不将 token 发给浏览器或写入日志。

PowerContext 参考版本 1.5.1，具体接口以安装包 OpenAPI 为准。可参考：
- POST /v1/scopes：title、summary、idempotency_key。
- POST /v1/memory/remember：scope_id、kind、text、reason。
- POST /v1/context/prepare：scope_id、query、max_bytes。
- 官方文档 https://powercontext.oceanbase.io/zh/docs/develop/api-quickstart/

项目标识由可信后端选择；scope_id 是数据分区不是授权。演示版若只支持单人本地使用，应明确限制，不宣称具备多租户隔离。

## 验收样例

使用全新的演示项目，依次执行：
1. 研究目标：比较两种番茄浇水方案。
2. 保存：已完成 A 组记录；B 组传感器故障；下一步更换电池后补采数据。
3. 关闭并重新打开应用，选回同一项目，查询“下一步做什么”。应召回更换电池和补采数据，不得声称 B 组已完成。
4. 新建另一个空白项目，不能召回上述实验记录。
5. 停止 PowerContext 后尝试保存，必须报失败；重启后验证已有记录仍然存在。

请真实运行这些样例，保存脱敏 HTTP 记录、测试输出和截图。预期结果与实际结果分开写；没有运行的步骤标为未验证。
